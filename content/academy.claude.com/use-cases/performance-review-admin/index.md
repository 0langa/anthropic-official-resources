# performance-review

Walk a Beacon Freight manager through one direct report’s review for the current cycle: gather input, score against the framework, draft in the template. Reads People / perf-cycle and the H2 calendar on Google Drive.

## This cycle

Self-reviews due 11 Sep. Peer input closes 18 Sep. Manager drafts due 2 Oct. Calibration 6–8 Oct. Conversations by 23 Oct 2026. (manager-cycle-instructions.pdf, H2 2026 review calendar)

## Step 1. Gather input

Read the report’s self-review, goals sheet and peer notes from their review folder. If there are fewer than two peer notes, tell the manager and continue. Where the written input is thin, ask the manager for two concrete examples per competency.

## Step 2. Score against the framework

Use only the six competencies in performance-framework-2026.pdf (Delivery, Craft, Ownership, Collaboration, Communication, Growing others) at the report’s level. For each: the evidence and where it came from, the level expectation quoted, and which rating definition the evidence matches.

## Step 3. Draft in the template

Fill review-template.docx sections 1–5 and 7. Mark any sentence the manager should replace with their own observation.

## Guardrails

1. Quote rating definitions exactly as written in rating-definitions.docx, in quotation marks, with the file name. Never paraphrase them.
2. Never score anything that is not one of the six competencies. If evidence does not fit one, say so and ask the manager.
3. Leave section 6, Overall rating, empty. The manager enters it (People team decision, 28 Aug 2026).
4. Nothing in section 7, For calibration only, is shown to the report.

Claude uses your definitions word for word and scores only your competencies.

### Why this works[](https://academy.claude.com/use-cases/performance-review-admin)

Prompt

**Ask for a reusable process.** "Help me build the /performance-review skill" makes the output the reusable process, so you author it once and every manager inherits the same steps.

Prompt

**Say what it must not make up.** "Quote our rating definitions verbatim and never invent criteria" keeps the skill anchored to the document in the folder, so calibration is comparing like with like.

Prompt

**List the steps in order.** Listing gather input, score, then draft tells Cowork the order your cycle instructions expect, so the skill matches the process you already trained managers on.

Source

**Let the working folder supply context.** The framework, rating definitions, and template sit in the working folder, so the skill is built from your current cycle documents and updates when you replace them.

### Get a better draft[](https://academy.claude.com/use-cases/performance-review-admin)

Practice

**Add an example to match.** Drop an example you like into the folder and Cowork matches your structure and voice.

Practice

**Ask it to flag uncertainty.** Add "flag anything you're not confident about" so you know where to look first when you review the draft.
