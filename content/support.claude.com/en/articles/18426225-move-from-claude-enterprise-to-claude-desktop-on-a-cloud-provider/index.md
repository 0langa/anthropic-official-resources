# Move from Claude Enterprise to Claude Desktop on a cloud provider

This guide explains how to move, or migrate, from Claude Enterprise to Claude Desktop on your own cloud provider. It covers what moves, what changes for users and admins, and the steps to take for Chat, Claude Cowork, and Claude Code.

This guide is for admins of organizations on Claude Enterprise plans.

This guide doesn't cover contracts, pricing, procurement, API workloads, or how to interpret compliance statements.

With Claude Enterprise, Anthropic hosts the models and stores your conversation history. The alternative is Claude Desktop on a third-party provider, which our docs call **Claude Desktop on 3P**. The desktop app **[routes all model inference through a provider you configure](https://claude.com/docs/third-party/claude-desktop/overview)**, so prompts and responses go through that provider. It can be Amazon Bedrock, Google Cloud's Agent Platform (formerly Vertex AI), Microsoft Foundry, or your own LLM gateway.

The move has two parts. You deploy Claude Desktop on 3P, and each user copies their own history into it.

## Before you begin

You'll need:

- An Owner or Primary Owner of your Claude Enterprise organization. Only the Primary Owner can run an **[organization export](https://support.claude.com/en/articles/13346720-export-your-organization-s-data)**.

- An admin for the cloud account, project, or subscription that will run inference.

- A way to deliver settings to devices: the **[Enterprise Admin Console](https://claude.com/docs/third-party/claude-desktop/admin-console)**, an **[MDM profile](https://claude.com/docs/third-party/claude-desktop/mdm)**, or a **[bootstrap server](https://claude.com/docs/third-party/claude-desktop/bootstrap)**.

- The latest Claude Desktop release on each device. A device that moves from an earlier third-party configuration to the console should be on 5.11492.0 or later before its user signs in, because earlier releases migrate fewer items. Session export needs 4.23118.0 or later on both devices.

## What to expect

- **Each user moves their own history.** Each user runs a one-time import on their own computer. Chats and projects come over, but uploaded files don't. See **[Import history from claude.ai](https://claude.com/docs/third-party/claude-desktop/import)**.

- **Work is stored on the device.** Conversation history, projects, and memory are stored on the user's computer. Prompts, responses, files, and tool outputs **[still go to your inference provider](https://claude.com/docs/third-party/claude-desktop/overview)**. There's no mobile app and no claude.ai web app. Claude runs only in the desktop app, on **[macOS and Windows](https://claude.com/docs/third-party/claude-desktop/installation) (Linux is in beta)**. Users can't share chats or projects with each other. See **[the feature comparison](https://claude.com/docs/third-party/claude-desktop/feature-matrix)**.

- **Your cloud provider bills you.** You pay for the tokens you use, and there are no seat licenses. See **[the feature comparison](https://claude.com/docs/third-party/claude-desktop/feature-matrix)**.

- **Your provider determines who processes your data.** On Amazon Bedrock and Google Cloud, the cloud provider processes conversation data in the region or routing option you choose, and the app **[doesn't send user data, prompts, or completions to Anthropic](https://claude.com/docs/third-party/claude-desktop/overview)**. On Microsoft Foundry, **[Anthropic operates the Claude models](https://claude.com/docs/third-party/claude-desktop/foundry)** as an independent processor for Microsoft. Some models add their own data retention and data sharing requirements. See **Compare cloud providers**.

You can run Claude Enterprise and Claude Desktop on 3P side by side during the move. Claude Desktop on 3P keeps its application data in a separate directory, **[so the two can coexist on one computer](https://claude.com/docs/third-party/claude-desktop/data-storage)**. They share a few folders, such as `~/Claude/` and `~/.claude/`. If you need to go back later, see **[Migrate Claude Desktop from a cloud provider to Claude Enterprise](https://claude.com/docs/third-party/claude-desktop/move-to-claude-enterprise)**.

Most of this guide applies to every provider. For details specific to Amazon Bedrock, Google Cloud, or Microsoft Foundry, see **Compare cloud providers**.

**Note:** Settings and version requirements change between releases. Check the linked page before you change a setting.

## What moves and what doesn't

The import brings over each user's own chats and projects, plus any Cowork and Code sessions already on their computer. Plan to move everything else by hand before your **cutoff date**, which is the last day users can access work in claude.ai. You set this date.

The import is a one-time copy. It doesn't stay in sync with claude.ai, but you can run it again to pick up newer chats **[without creating duplicates](https://claude.com/docs/third-party/claude-desktop/import)**.

### Replace shared projects

In Claude Desktop on 3P, **[projects live on each user's computer and aren't shared with other users](https://claude.com/docs/cowork/guide/projects)**. To give a team the same starting point, we recommend the following:

- **Shared instructions and reference material:** Package them as a skill or plugin and distribute it to everyone. See **Distribute skills and plugins**.

- **Shared files:** Keep them in the file sharing or repository tools you already use. Claude writes artifacts and scheduled-task results to **[`~/Claude/`](https://claude.com/docs/third-party/claude-desktop/data-storage)** in the user's home directory. In Cowork sessions, files that Claude creates in a project are saved in the project's folders.

### Move memory by hand

In claude.ai, each user can **[ask Claude to write out their memories](https://support.claude.com/en/articles/12123587-import-and-export-your-memory-from-claude)** and copy the text. They then paste what they want to keep into one of these places in Claude Desktop:

- **Global instructions:** Go to **[Settings > Cowork](https://claude.com/docs/third-party/claude-desktop/data-storage)**and click "Edit" next to Global instructions. They're included in every session.

- **Project instructions:** Add the text to a project's **[instructions](https://claude.com/docs/cowork/guide/projects)**. They apply to every session in that project.

## Set up the import tools

Claude Desktop includes tools for this move, and most are off until an admin turns them on. We recommend the latest Claude Desktop release.

### Turn on import

Both of these settings must be on before users can import history from your Claude Enterprise organization. Both are off by default.

1. **In claude.ai:** Have an Owner or Primary Owner go to **Organization settings > Data and privacy** and turn on **[Allow members to export their own data](https://support.claude.com/en/articles/13346720-export-your-organization-s-data)**.

2. **In Claude Desktop:** Turn on the import wizard. In the Enterprise Admin Console, go to **Capabilities** **> Claude.ai data import** and turn on **[Enable import](https://claude.com/docs/third-party/claude-desktop/admin-console)**. With MDM or a bootstrap server, set `enabled` to `true` under **[`claudeAiImport`](https://claude.com/docs/third-party/claude-desktop/configuration#claudeaiimport)**.

Users then go to **Settings > Import & export** and click "Import…" to open the **[import wizard](https://claude.com/docs/third-party/claude-desktop/import)**.

## Checklist for users

Share this checklist with each wave of users before they move. For the full walkthrough, see **[Import history from claude.ai](https://claude.com/docs/third-party/claude-desktop/import)**.

**Before you move, in claude.ai**

- Download any Word, Excel, PowerPoint, and PDF files Claude created for you, and export any artifacts you need in another format.

- Gather the original files you uploaded to projects and chats. They don't come over.

- Copy your memory and your **Instructions for Claude** (called Instructions in the newer Settings layout) into a local file.

- Download the skills you built from **Customize > Skills**.

- Make a note of the connectors you use, so you can ask for any that are missing.

**On the day you move, in Claude Desktop**

1. Open Claude Desktop and sign in the way your IT team described.

2. Go to **Settings > Import & export** and click "Import…" to open the wizard.

3. Click "Sign in to claude.ai…" and, in the browser, choose your work organization and click "Authorize."

4. Return to Claude Desktop and click "Fetch export," then "Continue."

5. Choose how far back to include local sessions in the **Cowork & Code** step, or skip the step.

6. Click "Import" in the **Review** step.

7. If a **Duplicates** step appears, choose "Merge into existing" or "Keep separate" for each project.

**After the import**

- Open each imported project. Review and accept its instructions, then add your files back. To use a project's folder in Chat, add the folder to the project again.

- Open an imported chat and send a message. Click "Trust and resume" when asked.

- Paste your saved memory and instructions into Claude Desktop.

- Reconnect the connectors you use.

- Run the import once more on your organization's cutoff date to pick up newer chats. It won't create duplicates.

## What changes for users

Most day-to-day work stays the same. Chat, Cowork, projects, artifacts, memory, scheduled tasks, file upload, skills, plugins, connectors, and Code are all **[features of Claude Desktop on 3P](https://claude.com/docs/third-party/claude-desktop/feature-matrix)**. The main differences are where work is stored and what admins control. Voice mode, Claude Security, and Claude Tag aren't available, and Claude in Chrome works only with the Enterprise Admin Console.

### Distribute skills and plugins

In Claude Desktop on 3P, you distribute skills and plugins through your configuration. For full details, see **[MCP, plugins, skills, and hooks](https://claude.com/docs/third-party/claude-desktop/extensions)**.

**Use a plugin marketplace (recommended):** Host a marketplace in git or over HTTPS and point to it with `allowedPluginMarketplaces`. You roll out updates by changing one configuration value instead of pushing files to every device. You can also **[set this in the console](https://claude.com/docs/third-party/claude-desktop/admin-console)**.

### Review web search and web fetch

Google Cloud and Microsoft Foundry support native search. On Google Cloud, an organization policy turns it off by default, so allow it there first. Amazon Bedrock doesn't, so you add a search provider. In Cowork and Chat, web fetch reaches only the hosts you list in **[`coworkEgressAllowedHosts`](https://claude.com/docs/third-party/claude-desktop/configuration#coworkegressallowedhosts)**. In Code, that list doesn't block fetches to other hosts. For who sees search queries, and how to limit, log, or turn off search, see **[Web search and web fetch](https://claude.com/docs/third-party/claude-desktop/web-tools)**.

Test web search before rollout on each operating system and each network your users work from, such as the office and home. If you add a search provider, its host **[must be reachable through your firewall and proxy](https://claude.com/docs/third-party/claude-desktop/web-tools#web-search)**. The app **[can't prompt for a proxy username and password](https://claude.com/docs/third-party/claude-desktop/network-proxy#default-behavior)**. If your proxy requires sign-in, such as with NTLM, plan extra testing. You may need a local forwarding proxy on each device that signs in to yours. Another option is a **[remote MCP search server](https://claude.com/docs/third-party/claude-desktop/web-tools#remote-search-mcp)** that you host.

To learn how we approach prompt injection, see **[Mitigating the risk of prompt injections in browser use](https://www.anthropic.com/research/prompt-injection-defenses)**, **[How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)**, and the **[Security](https://code.claude.com/docs/en/security)** page in the Claude Code docs. For security documents in the Trust Center, see the Security posture section of the **[overview](https://claude.com/docs/third-party/claude-desktop/overview)**.

## Plan your move

We recommend moving in **waves**, one set of users at a time, with an **overlap period** when both Claude Enterprise and Claude Desktop on 3P are running. Set a clear cutoff date, and give each user a short checklist to finish before they move. Keep claude.ai available until the last wave has imported.

### Phase 1: Plan for migration

**Who's involved:** AI program lead, IT, and your Anthropic account team

- Make the choices listed in **Decisions to make before your pilot**.

- Name one owner each for the cloud account, device management, identity, network, and communications and training.

- List what's in your Claude Enterprise organization: users, shared projects, skills your organization provides, and connectors in use.

- List the users who rely on the Claude mobile apps or on claude.ai in a browser, such as executives who work from a phone or tablet. Claude Desktop on 3P **[has neither](https://claude.com/docs/third-party/claude-desktop/feature-matrix)**, so decide whether those users keep Claude Enterprise seats.

- Agree on how you'll measure success, the order of your waves, and your cutoff date for claude.ai.

- Count who uses the Claude Code CLI. Note the server-managed settings, cloud sessions, and claude.ai connectors they depend on.

- List every sign-in your users will see, and note any IdP change planned for the same period. See **Plan identity and sign-in**.

- List the access programs, restricted models, and custom roles you use today. See **Plan for restricted models and access programs**.

### Phase 2: Set up the new environment

**Who's involved:** cloud, device management, network, and identity admins

- Enable or deploy the models with your provider, grant the inference role, and request enough quota for your users. Follow your provider's setup guide, linked in **Compare cloud providers**.

- Connect your IdP to the cloud provider and test sign-in with a small group.

- Run the **[Cowork readiness check](https://claude.com/docs/third-party/claude-desktop/installation)** on each hardware model. Cowork needs hardware virtualization and, on Windows, the Virtual Machine Platform feature.

- Package the app and test automated deployment with the team that manages your devices. Allow time for this work. On Windows, use the `.msix` package, which Cowork requires. **[Installing it needs administrator rights](https://claude.com/docs/third-party/claude-desktop/installation#install-the-app)**.

- Build the configuration in the console, or build it in the app and export it for MDM. Plan for the latest Claude Desktop release on every device.

- Decide which settings users shouldn't change, and set each one before the first user signs in. For example, Code offers Auto mode unless you set **[`autoModeEnabled`](https://claude.com/docs/third-party/claude-desktop/configuration#automodeenabled)** to `false`. Deliver these settings from the console, an MDM profile, or a bootstrap server, because **[users can edit the local configuration file](https://claude.com/docs/third-party/claude-desktop/configuration-format#which-configuration-source-applies-on-a-device)**. The console alone doesn't keep a device on your settings. To enforce them, also **[deploy `forceLoginOrgUUID`](https://claude.com/docs/third-party/claude-desktop/admin-console#limit-claude-desktop-to-your-organization)** in a machine-level managed profile. The key limits which organizations users can sign in to in Claude Desktop, so list your Enterprise Admin Console organization and every other organization they still need during the overlap period. Then check on a test device which settings users can still change. With MDM, confirm that the in-app configuration window **[opens read-only](https://claude.com/docs/third-party/claude-desktop/installation#verifying-the-deployment)**. On Windows, a misspelled value also locks the window, so compare each value in the diagnostic report's `managed-config.txt` with the value you set.

- Open the **[required network hosts](https://claude.com/docs/third-party/claude-desktop/telemetry)**, and allow the app in your endpoint security tools by its **[signing identity](https://claude.com/docs/third-party/claude-desktop/installation)**.

- Configure connectors, the plugin marketplace, web search, the banner, the token cap, and OpenTelemetry export.

- Set up model access rules at the provider and in the app's model list.

- Set budget alerts with your provider, and turn on cost attribution before the first user signs in.

- For CLI users, deploy Claude Code managed settings with the provider variables, pinned models, model limits, and `allowedProviders`. See **Move Claude Code CLI users**.

- If you hold an access program grant, link the cloud account in the Verification Portal and turn on access. Allow for the lead time.

### Phase 3: Prepare your existing users

**Who's involved:** Owner, Primary Owner, and communications lead

- Turn on member data export and the import wizard. See **Turn on import**.

- Choose any optional import settings, such as the import prompt, the organization allowlist, and rollout by group.

- Confirm that devices can reach the **[hosts that sign-in import needs](https://claude.com/docs/third-party/claude-desktop/telemetry)**.

- Have the Primary Owner run an **[organization export](https://support.claude.com/en/articles/13346720-export-your-organization-s-data)** for your records. The download link expires after 24 hours and may work only once, so download the file right away.

- Send each wave the **Checklist for users**, along with your cutoff date.

- Send developers the **Checklist for developers**, so they pull down cloud sessions before the cutoff date.

- Postpone any changes to the claude.ai SSO connection and SCIM directory until the last import, or schedule the switch between waves.

### Phase 4: Run a pilot, then move in waves

**Who's involved:** device management, your champions, and your Anthropic account team

- **[With MDM or a bootstrap server,](https://claude.com/docs/third-party/claude-desktop/mdm)** **[deploy the configuration first, then the app](https://claude.com/docs/third-party/claude-desktop/mdm)**, so users open the app directly into Claude Desktop on 3P. With the console, **[save the configuration first, then have users install the app and sign in](https://claude.com/docs/third-party/claude-desktop/installation)**.

- Check a device with **Help > Troubleshooting > Generate Diagnostic Report**. In the exported file, **[`deployment-mode.txt`](https://claude.com/docs/third-party/claude-desktop/installation)** shows whether the app is in third-party mode.

- Pilot with a mix of roles. Where they apply, include a CLI developer, a user of each restricted model, and a user from each identity group.

- Test the import, each connector, web search on each network users work from, the Primary Owner's history, and what users see when a request is flagged. Also test resuming a CLI session, cost reporting by user, and how spend appears in your provider's billing console.

- Fix what the pilot finds and update your user guide. Then move each wave, with launch training and office hours.

- For each wave, track how many users have installed the app, signed in, imported, and are still active in week two. The **[`desktop_claude_ai_import`](https://claude.com/docs/cowork/changelog)** event in your telemetry is logged for each claude.ai history import. Users can import more than once, so count distinct users. It's an info-level event, so set `otlpDesktopLogLevel` to `info` to receive it.

### Phase 5: Wind down Claude Enterprise

**Who's involved:** Primary Owner, identity admins, and network admins

- On the cutoff date, have users finish their work in claude.ai and run the import one last time. Do this before you block claude.ai on your network, because sign-in import needs it. If you use the console, **[don't block `claude.ai`, `api.anthropic.com`, or the `hcaptcha.com` hosts](https://claude.com/docs/third-party/claude-desktop/admin-console#where-your-data-goes)**. Limit `claude.ai` and `api.anthropic.com` to your organizations with Tenant Restrictions instead. With MDM or a bootstrap server, the app also **[reads its update feed](https://claude.com/docs/third-party/claude-desktop/telemetry#required-egress-paths)** from `claude.ai` and `api.anthropic.com` by default. Before you block them, set `updateViaUpdatesHost` to `true` and allow `releases.claude.com`, or turn off auto-update and distribute new versions yourself. In Code sessions, Web Fetch checks each domain with `api.anthropic.com` and refuses the fetch if it can't, so also set `skipWebFetchPreflight` to true before you block that host. Keep admin access after the cutoff date, so you can run final exports and remove users.

- Keep users in the new deployment. With MDM or a bootstrap server, set **[`deploymentMode`](https://claude.com/docs/third-party/claude-desktop/mdm#restrict-a-device-to-one-deployment-mode)** to `3p` in the managed profile that sets your provider or bootstrap keys (Claude Desktop 4.16336.0 or later). Until every device has updated, also set `disableDeploymentModeChooser` to `true` in the profile and, with a bootstrap server, in its response. Don't set either key on devices that use the console. With the console, turn on **[Require this organization in Claude Desktop](https://claude.com/docs/third-party/claude-desktop/admin-console#users-in-more-than-one-claude-organization)** so members of both organizations must switch. That setting doesn't enforce sign-in. To enforce it, remove your Claude Enterprise organization's ID from `forceLoginOrgUUID` after the last wave has moved, except for users who keep Claude Enterprise.

- For CLI users, narrow `allowedProviders` to the new provider, except on computers where users stay signed in to claude.ai in Claude Desktop, and retire your server-managed settings.

- Control personal accounts on your domain and network with **[Restrict organization creation](https://support.claude.com/en/articles/13132885-set-up-single-sign-on-sso)** and **[Tenant Restrictions](https://support.claude.com/en/articles/13198485-enforce-network-level-access-control-with-tenant-restrictions)**. If you use the console, include the new organization's ID in the allowed list.

- Run a final organization export and **[audit log export](https://support.claude.com/en/articles/9970975-access-audit-logs)**. A removed user's data **[is still included in the Primary Owner's exports](https://support.claude.com/en/articles/12053672-what-happens-to-a-user-s-data-when-they-are-removed-from-a-team-or-enterprise-organization)**.

- Some work may have to stay on Claude Enterprise, for example under an access program your cloud provider doesn't support yet, or for users who need the mobile apps. If so, keep those seats and reduce the size of the organization instead of closing it.

- Remove users. With SCIM, users you remove from your IdP app **[are removed automatically](https://support.claude.com/en/articles/13133195-set-up-jit-or-scim-provisioning)**. With JIT, they stay in your member list until an admin removes them. A user you remove only in Claude is added again the next time they log in with SSO. If your Enterprise Admin Console organization shares the SCIM directory, check how removing users from the IdP app affects it first. Removed users **[lose access immediately](https://support.claude.com/en/articles/13133750-manage-members-on-team-and-enterprise-plans)**, but removal **[doesn't delete their account or data](https://support.claude.com/en/articles/12053672-what-happens-to-a-user-s-data-when-they-are-removed-from-a-team-or-enterprise-organization)**.

- To clear stored data sooner, you can shorten your **[custom data retention period](https://support.claude.com/en/articles/10440198-configure-custom-data-retention-controls-for-enterprise-plans)**. Anything outside the new period is scheduled for permanent deletion as soon as you save, so finish your exports first. The minimum period is 30 days, and it doesn't cover the memory of users you've already removed. Chats in projects follow the project retention period instead, and artifacts published with a public link aren't deleted.

- Before you close anything, confirm with your Anthropic account team which domain and SSO settings the new deployment still relies on. Then talk to them about ending the plan. To delete the organization, the Primary Owner **[sends a request to Support](https://support.claude.com/en/articles/12053672-what-happens-to-a-user-s-data-when-they-are-removed-from-a-team-or-enterprise-organization)**.
